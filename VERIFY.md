# VERIFY: what the design relies on, and how we know

Every behavior of Amazon Connect or of the flow-as-code tools that Hollow Hour
builds on has a row here, with the AWS documentation that says so and what the
answer forced us to change. `tests/verify.test.ts` fails when a row loses its
AWS doc link or its status.

Status is one of:

- **docs-checked 2026-09-30**: the AWS documentation says it, quoted or
  paraphrased closely, and where the row names flow-as-code behavior, the
  published 0.2.0 packages or the flow-as-code repository confirm it.
- **needs sandbox**: the documentation is silent, ambiguous, or has never been
  shown to hold against the service. The design does not depend on the
  answer until a live create or run records one.

When a sandbox check runs, the status becomes
`sandbox-checked YYYY-MM-DD, <region>: <result>` in the same row, where the
date is the UTC date the call ran (`date -u`), the Region is the instance's
(for example `us-west-2`), and the result is `accepted` or the service's
refusal message, quoted as returned with any account id cut to its last four
digits. `tests/verify.test.ts` holds that shape. The first rows were checked
against the documentation alone. On 2026-09-30, after dev and qa were
applied, the probes recorded here ran against the dev instance (then in
us-west-2; dev moved to us-east-1 later that day, row R1):
each probe resource was created, described and deleted, and nothing else on
the instance was changed. Row S2 also ran on qa and on prod (both us-east-1). A row that says "Not decidable by a create" needs
more than a create or describe on dev, and names what.

"Rule N" means `conformance/flow-language/actions.md` rule N in flow-as-code,
which the published catalog follows.
